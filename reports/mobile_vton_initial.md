# Mobile-VTON 초기 테스트 — 2026-10-23

공식 공개 체크포인트로 **1024×768 이미지 추론에 성공**했다. 같은 입력과 시드로
28스텝 추론을 두 번 실행했으며 PNG 해시와 출력 픽셀이 모두 일치했다.
이번 결과는 RTX 3080 Laptop GPU에서의 기능·자원 측정이다. 휴대폰 추론은 아직 실행하지 않았다.

## 실측 결과

| 항목 | 결과 |
| --- | --- |
| GPU | NVIDIA GeForce RTX 3080 Laptop GPU, 16GB급 |
| 해상도 / 배치 / 정밀도 | 768×1024 / 1 / BF16, 최종 디코더 FP32 |
| 스텝 / guidance / seed | 28 / 2.5 / 42 |
| 파이프라인 시간 | 17.080초, 17.116초; 평균 **17.098초/장** |
| GPU peak allocated | **5,022,394,880 bytes = 5.02GB = 4.68GiB** |
| GPU peak reserved | 5,874,122,752 bytes = 5.47GiB |
| 가중치 로드 구간 | 3.621초; 파일 캐시가 있는 상태이며 앱 cold start 측정은 아님 |
| 전처리 + 텍스트 인코딩 | 0.315초, 이후 반복 실행에서 재사용 |
| 공식 checkpoint 디렉터리 | **3,755,403,203 bytes = 3.76GB = 3.50GiB** |
| 실제 로드된 전체 파라미터 | **1,783,951,046개, 약 17.84억** |

추론 시간은 VAE 인코딩, 이미지 특징 추출, diffusion, 디코딩과 NumPy 출력 변환을
포함한다. 모델 로드, 이미지 전처리, 텍스트 인코딩, PNG 저장은 제외하며 앞의 두 항목은
별도로 측정했다. 1스텝 워밍업 후 측정했다. 데스크톱의 다른 GPU 프로세스를 종료하지
않은 공유 환경이므로 독점 GPU 벤치마크나 휴대폰 성능으로 해석하면 안 된다.

## 크기 해석 정정

앞서 인용한 **415M은 주 생성기인 TryonNet 규모**이며 전체 파이프라인 크기가 아니다.
공개 파일에는 아래 구성요소가 함께 있다. 이 표의 파라미터 수는 실제 로드된
`module.parameters()` 기준이며, safetensors 헤더의 모든 텐서 수에는 버퍼도 포함된다.

| 구성요소 | 실제 파라미터 | 배포 파일 크기(십진 MB) |
| --- | ---: | ---: |
| TryonNet | 415,878,672 | 840.17 |
| GarmentNet | 377,459,472 | 759.20 |
| DINOv2 이미지 인코더 | 86,580,480 | 173.19 |
| CLIP 텍스트 인코더 | 123,650,304 | 247.32 |
| 두 번째 CLIP 텍스트 인코더 | 694,659,840 | 1,389.38 |
| VAE | 83,819,683 | 335.31 |
| 경량 VAE 디코더 | 1,902,595 | 7.64 |

전체 checkpoint의 25개 파일 크기와 7개 가중치 파일 SHA256을 공식 Hugging Face
메타데이터와 대조해 모두 확인했다. 따라서 이전의 약 830MB 추정은 주 생성기의
FP16/BF16 가중치만 설명하며 전체 앱의 모델 다운로드 용량을 설명하지 못한다.

## 첫 샘플의 시각적 관찰

- 보라색 반팔 상의를 회색 긴팔 가디건으로 교체했다. 민트색 테두리, V넥, 전면 여밈이 반영됐다.
- 바지, 신발, 대략적인 자세와 배경은 유지됐다. 전체 이미지를 다시 생성하므로 원본 픽셀 보존은 보장되지 않는다.
- 스누피 그래픽, 단추, 니트의 미세 질감은 원상품과 차이가 있다. 상품 디테일 보존이 평가 과제다.
- 한 사람·한 의류 조합의 기능 확인이다. 체형·포즈·의류 종류별 품질 결론이나 벤치마크 점수는 내리지 않았다.

## 모바일 판단과 남은 테스트

연결된 기기는 Android 13 / SM8150 기반 Pixel 4로, 전체 RAM은 약 5.34GiB이고
초기 관찰 시 가용 RAM은 약 394MiB였다. 앱이나 기기 설정을 바꾸지 않았다.
데스크톱 GPU 메모리 값을 이 기기의 RAM 요구량과 직접 동일시할 수 없으며, 현재
공개 체크포인트를 그대로 모바일 배포할 수 있다고 판단할 근거는 없다.

논문 부록 A는 모바일 INT8/NPU 환경에서 1024×768 한 장에 약 80초를 보고한다.
이는 저자의 보고이며 이번에 재현한 수치가 아니다. 공개 코드에는 그 모바일
양자화 가중치·변환 스크립트·Android/iOS 런타임이 포함되어 있지 않다.
사진 생성의 품질 기준선으로는 유지하되, 실시간 카메라 경로의 후보로 선정하지 않는다.
다음 검증은 모바일 export와 구성요소 분리·캐시·양자화 가능성 확인이다.

## 재현 정보

코드 `57410f20ac0e1703af795702e10473565feaa711`, 가중치
`0063147c171518b391fff5e44d04555c12370c35`를 고정했다. 공유 Python 환경은 변경하지 않았다.
원본 연구 코드는 유지하고 단일 쌍 실행·측정용 래퍼만 추가했다. 사용한 Diffusers는
0.34.0으로 upstream 환경 파일의 0.32.2와 다르다. 의류 설명과 negative prompt를
래퍼에서 지정했으므로 논문의 전체 평가 프로토콜을 그대로 재현한 결과는 아니다.
입력 샘플은 CatVTON의 공개 예제이며 출처·해시를 기록했고 Git에서 제외했다.

```bash
conda run --no-capture-output -n comfyui python scripts/run_mobile_vton.py --config experiments/2026-10-23-mobile_vton/config.json
```
